# 规模评估：当前本体有多少“节点”，以及是否太少

> 评估日期：2026-11 · 对应版本：1.8.0 · 范围：`ontology/**/*.ttl`

用户反馈“节点数量有点太少”。这个判断需要区分三种“节点”口径，否则容易把三元组、IRI、类和实例混在一起。
以下是 1.8 扩展后快照（40,574 条三元组）的拆解与结论。

---

## 1. 当前规模

### 1.1 RDF 基础口径

| 指标 | 数量 | 说明 |
| --- | ---: | --- |
| 三元组 | 40,574 | 七层合并后的 RDF 图 |
| 唯一 RDF 术语 | 12,684 | subject + predicate + object 去重 |
| 其中 IRI | 4,062 | 命名空间中的资源 |
| 其中 blank node | 2,059 | RDF list、限制、SWRL 原子、ODRL 规则等结构节点 |
| 其中 literal | 6,563 | 标签、定义、数值、日期等 |
| 唯一 subject | 5,895 | 被描述的资源 |
| 唯一 predicate | 390 | 使用的属性 |
| 唯一 object | 12,109 | 对象资源或字面量 |

“12,684 个唯一术语”听起来不少，但其中大量是 RDF list、SWRL 原子、ODRL 规则等**结构节点**，
不是领域概念。评估本体覆盖度时，更有意义的是下面的“可浏览实体”。

## 2. 结论：少不少，取决于目标

### 2.1 作为“七层贯通的可运行参考模型”

**不算少。** 当前规模已经能：

- 用一条完整决策链串起 RDF → RDFS → OWL → SKOS → SWRL → OWL-S → ODRL；
- 支撑 10 条能力问题；
- 在页面上展示 294 个类、451 个属性、147 个概念、151 条规则、3,404 个可浏览实体；
- 覆盖价值筛选、财务风险、ST 排除、止损、集中度、限制名单、可审计性，以及
  ETF 跟踪误差、可转债溢价、未审批订单、基金流出等扩展逻辑。

这是一个“结构完整、可执行、可演示”的最小闭环，而不是只堆标签的示例。

### 2.2 作为“生产级 A 股行业本体”

**仍然偏小。** FIBO 是金融行业级本体，按 Foundations、Business Entities、Securities、
Indices and Indicators、Market Data 等模块组织，类和关系的数量远高于本项目；它背后还有多年的
行业治理、映射和维护。当前 246 个类覆盖了 A 股投研、短线交易与游资方法论的骨架，但仍不足以覆盖真实全流程。

更重要的是：**节点数量本身不是质量指标。** 如果为了“看起来多”而加入大量没有定义、没有关系、
没有能力问题支撑的孤立类，只会降低本体质量，增加维护和推理成本。

## 3. 主要覆盖缺口

按业务优先级，当前最明显的缺口是：

### 3.1 工具与市场广度

- 基金、ETF、LOF、REITs；
- 债券、可转债、回购；
- 股指期货、商品期货、期权；
- 指数编制、成分股、权重、调样；
- 交易日历、停复牌、涨跌停、竞价与订单簿；
- 北向/南向、融资融券、质押、限售解禁。

### 3.2 公司与公司行为

- 股权结构、实际控制人、一致行动人；
- 子公司、参股公司、关联方与关联交易；
- 分红、送转、回购、定增、可转债转股；
- 并购重组、资产注入、分拆上市；
- 业绩预告、业绩快报、业绩修正；
- 股权激励、员工持股、增减持。

### 3.3 财务与估值深度

- 三张报表的完整科目与科目映射；
- 分部/地区收入、客户与供应商集中度；
- 非经常性损益、扣非利润、现金流质量；
- 分析师一致预期、盈利预测、评级与目标价；
- 估值分位、历史区间、可比公司。

### 3.4 决策与组合深度

- 因子体系：价值、成长、质量、动量、低波、红利；
- 风险模型：暴露、协方差、跟踪误差、回撤、压力测试；
- 组合优化：权重、行业/风格/流动性约束、换手约束；
- 回测、归因、交易成本、滑点；
- 订单、成交、执行算法、人工审批与审计；
- 适当性、冷静期、集中度、限制名单、内幕信息隔离。

### 3.5 研究、舆情与 ESG

- 新闻、公告、研报、电话会议、互动易；
- 情绪、主题热度、事件冲击；
- ESG 指标、争议事件、碳数据；
- 供应链与产业链关系。

### 3.6 数据治理与合规

- 数据授权、用途、地域、期限（ODRL 已起步）；
- 数据质量、缺失、修订、版本、血缘；
- 监管规则、披露时限、静默期；
- 模型风险、可解释性、人工复核记录。

## 4. 建议的扩展路线（不是一次性堆节点）

### P0：决策深度（优先）

- 新增约 30–60 个类、40–80 个属性、5–10 条规则；
- 重点：因子、风险模型、组合约束、订单/执行、合规检查；
- 验收：新增 10–15 条能力问题，且每条都能被 SPARQL/SWRL 回答。

### P1：工具与市场广度

- 新增约 80–150 个类、100–200 个属性；
- 重点：基金/ETF、债券/可转债、期货/期权、指数与成分、交易日历；
- 同步扩展 SKOS：行业细分、主题、资产类别、策略标签。

### P2：公司与财务深度

- 新增约 50–100 个类、100–200 个属性；
- 重点：股权、公司行为、三张报表科目、分析师预期；
- 需要与真实数据源和授权分类标准对齐。

### P3：生产治理

- 数据授权、质量、血缘、模型风险、人工审批；
- 目标不是“类更多”，而是**每个决策字段都有来源、规则、版本和责任人**。

上述数字是规划量级，不是承诺；实际应以能力问题覆盖率和数据可用性为准，而不是以节点数验收。

---

## 5. 比“节点数”更值得跟踪的指标

1. **能力问题覆盖率**：10 条中多少能被完整回答；
2. **孤立节点比例**：没有任何关系或实例的类/属性应被清理；
3. **属性/类比**：属性过少通常意味着类只是标签；
4. **实例覆盖率**：每个核心类是否有示例个体；
5. **公理密度**：限制、键、不相交、规则是否覆盖关键约束；
6. **可追溯率**：决策是否有证据、规则版本、服务、政策、合规检查；
7. **数据新鲜度与授权**：真实场景下的硬约束。

当前项目的 3,404 个可浏览实体、294 个类，适合作为**参考实现和演示**；如果目标改为
生产级，应按上面的路线扩展，并把新增节点接到能力问题、数据源和治理流程上。
